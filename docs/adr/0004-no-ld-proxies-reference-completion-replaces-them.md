# No LD proxies: Reference Completion replaces them

opengwasr offers no proxy lookup when fetching Associations. ieugwasr's `proxies = TRUE` (fetch a nearby variant in LD when the requested one is missing, then realign alleles) is superseded by Reference-Completed Store Releases, which already hold an Imputed Association for variants the source did not report. A caller that would have asked for proxies gets the Imputed Association instead, labelled by its Association Status. We chose this because proxy substitution answers a question about a different variant, depends on whichever LD reference the client happens to use, and repeats work opengwasdb already did once, consistently, when it built the Store.

Clumping does stay in opengwasr. It is composed on the client (top hits, then `ld/clump` on an LD Store, scored by |z|), and it is on by default in `og_tophits()`. Its default thresholds belong to the LD Store, not to opengwasr: a 10 Mb window at that LD Store's lowest stored r² (its t_far). So the default is always a request the LD Store can answer exactly, never an approximation of TwoSampleMR's old r² 0.001 / 10 Mb. The LD Store is matched by the Analysis's Assigned Ancestry. When several LD Stores share an ancestry, the default the LD Store list declares wins. An Unassigned Analysis, or a set of Analyses whose ancestries differ, is refused unless the caller names an LD Store: there is no EUR fallback. Every clumped result records the LD Store, the r² and window applied, and how the LD Store was chosen. Clumping against the user's own PLINK Reference, as ieugwasr's local functions do today, is kept. The LD used is chosen by its own argument, independent of the Source the Associations came from, so Associations from a Local Source can be clumped through the API. Variants are matched to a PLINK Reference by rsID, since those references are usually GRCh37, and variants it lacks are dropped with a message giving how many. Reading downloaded LD Stores locally is deferred. It is planned to be replaced by a pre-clumped top-hits component of OpenGWAS Stores once ogld is stable.

**Consequences:** TwoSampleMR's `proxies`, `rsq`, `align_alleles`, `palindromes` and `maf_threshold` arguments to `extract_outcome_data()` lose their meaning and have to be retired or redefined.
